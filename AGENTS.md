# AGENTS.md

React 19 + TypeScript + Vite app for creating and viewing GitHub issues. Uses TanStack Router, TanStack Query, Supabase auth, Tailwind CSS and TipTap.

## Code style

### Naming

- `camelCase` for variables and functions, `PascalCase` for components and types.
- Booleans are prefixed `is`/`has`/`should` (e.g. `isLoading`, `hasToken`).
- Event handlers are `handleXxx` inside a component and `onXxx` when passed as props (e.g. `onTitleChange(value)`).
- `props` is reserved for component parameters; plain functions and callbacks use `params`.
- Prefer descriptive names over generic ones; avoid vague suffixes like `Data`, `Info`, `Misc`, `Helper`.
- Route files follow TanStack Router file conventions: lowercase, hyphen-separated (`create-issue.tsx`), with `$param` for dynamic segments.

### TypeScript

- No `any`. Use `unknown` and narrow it, or write a proper type.
- Use `import type` for type-only imports.
- Type component props with a named `type` (e.g. `type IssueCardProps = { ... }`), not inline.
- Prefer `type` over `interface` unless declaration merging is needed.
- Handle `null`/`undefined` explicitly (`??`, optional chaining); no non-null assertions (`!`) without a comment explaining why.
- No unused variables, parameters or imports (the TS config enforces `noUnusedLocals` and `noUnusedParameters`).
- Only disable lint or type rules with a comment justifying it.

### React

- Function components only, one exported component per file.
- Follow the Rules of Hooks; keep `useEffect` dependency arrays complete, and don't use effects for values that can be derived during render.
- Server data goes through TanStack Query (`useQuery`/`useMutation`), not `useEffect` + `fetch` + `useState`.
- Forms use `react-hook-form`.
- Shared logic belongs in `src/utils/` or a custom hook, not copied between components.

### Styling

- Use Tailwind utility classes. Avoid inline `style={{}}` and new CSS files unless Tailwind can't express it.
- Remove stray whitespace in `className` strings.

### Formatting

- Semicolons at the end of statements, single quotes for strings.
- Keep a file consistent with itself; don't mix formatting styles in one file.

### Clean code

- No leftover `console.log` or debug code in committed changes. Never log tokens, secrets or user data.
- No commented-out code; delete it.
- No magic numbers or strings; name them as constants.
- Keep functions and components small and focused on one job.

## Files to skip

- `src/routeTree.gen.ts` is generated by TanStack Router. Never edit or review it.
